## স্ক্যানের পর auto-copy recovery + বটের live transfer screen

বটের Admin panel → **📥 Download / Upload লাইভ**, অথবা `/downloads`। স্টোরে ঢুকলে পাবেন:

- চলমান ভিডিওর নাম ও download / thumbnail / upload / Telegram-side copy ধাপ;
- আসল byte callback থেকে কত MiB/কত শতাংশ হয়েছে, গড় গতি এবং **বর্তমান ধাপের** আনুমানিক বাকি সময়;
- সফল/ব্যর্থ/অপেক্ষমাণ/চলমান সংখ্যা, retry/FloodWait countdown, সেশন নেই/worker heartbeat নেই/lease ব্যস্ত—নির্দিষ্ট কারণ;
- আসল **store cache channel**-এর ID ও খোলার বাটন। Public publish channel আলাদা হলে সেটিও জানায়; সেটিংস না বদলে ভিডিও অন্য public channel-এ publish করে না।

স্টোরের অটো-প্রগ্রেস মেসেজ প্রায় ৫ সেকেন্ড পরপর আপডেট হয়; `/downloads` overview খোলার পরে সর্বোচ্চ ১০ মিনিট auto-refresh (আবার খুললে আবার শুরু)। Restricted downloader-এর byte progress-ও একই overview-তে দেখা যায়। ETA পুরো queue-এর নিশ্চয়তা নয়; source সরাসরি forward হলে server download লাগে না, তাই সেখানে ভুয়া MB/ETA দেখায় না।

### যে auto-start সমস্যাগুলো সংশোধিত

1. স্ক্যান মাঝপথে নেটওয়ার্কে ব্যর্থ হলেও তার আগেই সেভ হওয়া ভিডিও এখন finally-block থেকে queue-তে যায়।
2. আগের scan-এর `FILE_*` rows / scan-audit মিলে এমন missing jobs startup বা `/downloads` থেকে backfill হয়—পুরোনো পোস্ট বা source ID বদলানো ছাড়াই। Manual upload এবং explicit Pause/Stop অপরিবর্তিত।
3. scheduler জাগানোর আগে channel bootstrap শেষ হওয়ার অপেক্ষা করে না; বড় legacy warmup-ও আর queue wakeup আটকে রাখে না।
4. Backup/extra bot-এ scan করলেও সেটির আলাদা transfer monitor চলে। মূল বটের ওপর একা নির্ভর করে না; SQLite shared lease-এর জন্য একসঙ্গে সর্বোচ্চ ৩টি transfer-ই চলে, duplicate broadcast scheduler শুরু হয় না। যে worker কাজ করবে সেখানে মালিকের সংযুক্ত session লাগবে।
5. Session না থাকলে নীরবে থেমে থাকা বা queued-কে “চলছে” বলা বন্ধ। ডেটাবেজে blocker/progress থাকে, retry বাটনও থাকে। Pause/Stop নিজে থেকে তুলে দেওয়া হয় না।

**যাচাই:** ৫৭৯টি offline test, নতুন ১৭টি progress/recovery test-সহ; scan → স্বয়ংক্রিয় download → upload এবং byte callbacks-সহ integration test আছে। Production Telegram transfer/হোস্টের লগ আলাদাভাবে যাচাই করতে হবে। পরিবর্তন চালু করতে hosting-এ এই branch deploy/restart করুন।

## শুধু ভিডিও স্ক্যান + Restricted download

- সেশন ও bot scan দুটিতেই Telegram video filter এবং ভিডিও-only যাচাই। ছবি/ডকুমেন্ট স্ক্যানে নতুন করে ঢুকবে না; manual upload-এর আলাদা নীতি অপরিবর্তিত। Bot scan-এর ভিডিওও store archive queue-তে যায় (copy করতে মালিকের সেশন লাগবে)।
- নতুন ভিডিও upload-এ `video/*` MIME, সঠিক extension/filename, `DocumentAttributeVideo`, duration/dimensions এবং `supports_streaming=True`, `force_document=False`। পুরোনো source filename `.bin` নতুন upload-এ বহন করা হয় না। এটি arbitrary ফাইলকে rename করে ভিডিও বানানো বা transcode করা নয়; source ভিডিওর সঠিক format/attributes বহন করা। Internal web byte-cache-এর `.bin` নাম Telegram upload-এর filename নয়।
- দ্রুত ৩টি transfer একসঙ্গে; ইচ্ছাকৃত default cooldown নেই। আগে নিজে `VIDEO_COPY_DELAY` সেভ করে থাকলে Emergency settings থেকে ০ করুন। Telegram FloodWait, disk/size limits সবসময় কার্যকর—অসীম download speed দাবি নয়।

### বট থেকে ব্যবহার

1. `/session` দিয়ে নিজের সেশন কানেক্ট করুন। Admin panel → **📥 Restricted download**, অথবা `/restricted`।
2. **চ্যানেল তৈরি / চালু** বাটন বা `/restricted on` দিন। নিজের সেশন আলাদা private broadcast channel বানাবে এবং বটকে admin করবে। চ্যানেলের লিংক বটেই পাবেন।
3. **ওই চ্যানেলে** একটি পোস্টের পুরো লিংক পাঠান: `https://t.me/channel/123` বা `https://t.me/c/1234567890/123`। User session-কে সোর্সে আগে থেকেই বৈধ অ্যাক্সেস থাকতে হবে; invite-only/inaccessible উৎস নিজে থেকে খোলা হয় না।
4. একক পোস্ট বা album-এর ছবি/ভিডিও/ডাউনলোডযোগ্য document সেখানে **ক্যাপশন ছাড়া** আবার upload হবে। Album-এর মাঝের media-র লিংকও সমর্থিত। Media আলাদা native photo/video message হিসেবে আসতে পারে; album grouping হুবহু রাখা হচ্ছে না।
5. **এই আলাদা চ্যানেলের কপি forward করা যাবে**। পুরোনো store/source channel-এর protection এবং কোনো পুরোনো প্রকাশিত পোস্ট বদলানো হয় না।
6. `/restricted off` নতুন কাজ থামাবে; in-flight upload শেষ হতে পারে। `/restricted retry` বা retry বাটন ব্যর্থ পোস্টের অসম্পন্ন media চালাবে—checkpoint থাকা সফল media আর upload হবে না।

শুধু registered admin-created broadcast channel-এর link গ্রহণ করা হয়; user-sender হলে admin অনুমতি পরীক্ষা হয়। প্রতিটি Telegram update একবার queue হয়। Queue/checkpoint/channel registry পূর্ণ database backup-এ থাকে। Restart-এ main scheduler কাজ ফেরায়; store-copy ও এই downloader একই SQLite lease ব্যবহার করে, মিলিয়ে সর্বোচ্চ ৩টি transfer। সফল/ব্যর্থ/বাতিল transfer-এর temp folder মুছে যায় (SIGKILL/power loss-এ cleanup চালানো সম্ভব নয়)।

এই আপডেটের পরীক্ষা: নিচের test suite offline/mocked Telegram দিয়ে চালানো হয়েছে; production session দিয়ে actual download/upload ও client playback আলাদাভাবে যাচাই করতে হবে। নতুন কোড deploy/restart করুন (`python run.py`)।

## স্ক্যান → স্বয়ংক্রিয় ভিডিও আর্কাইভ

`Promt.py` / `protm.py`-এর নির্দেশনা এবং `DownloadRestricted-example.py`-এর download/upload লজিক বর্তমান সিস্টেমে যুক্ত হয়েছে; উদাহরণের আলাদা ওয়েবসাইট বা hardcoded credentials ব্যবহার করা হয় না।

1. নিজের সংযুক্ত Telegram সেশন দিয়ে স্টোরে চ্যানেল স্ক্যান করুন। শেষ হলে ওই সোর্সের **শুধু ভিডিও** কপি-জবে যোগ হবে; স্ক্যানের সময় ছবি/অন্য ফাইল যোগ হবে না; আগের প্রকাশিত কনটেন্ট মুছবে না। একই সোর্স পুনরায় স্ক্যান করলেও অসম্পন্ন কাজ যোগ হয়, সম্পন্ন কাজ রিসেট হয় না।
2. স্টোরের নিজস্ব প্রাইভেট ক্যাশ চ্যানেল তৈরি/পুনর্ব্যবহার হবে। পুরোনো shared cache বা source-as-mirror-কে আলাদা স্টোর আর্কাইভ ধরা হয় না। প্রথমে Telegram forward; ব্যর্থ হলে সেশন দিয়ে download → upload, ভিডিও attributes ও thumbnail রাখা হয়। সোর্সের আইডি/প্রকাশিত লিংক বদলায় না।
3. সর্বোচ্চ **৩টি ভিডিও একসঙ্গে**, পুরোনো মেসেজ আগে; প্রতি slot-এ ডিফল্ট অতিরিক্ত বিরতি নেই (`VIDEO_COPY_DELAY=0`, ০–৩০ সেকেন্ড)। FloodWait-এ Telegram-এর অপেক্ষা মেনে চলে; দীর্ঘ FloodWait-এর deadline ডেটাবেজে থাকে, চেষ্টা নষ্ট হয় না। অন্য ব্যর্থতায় সর্বোচ্চ ৩ চেষ্টা, তারপর পরের ফাইল।
4. আপলোড সফল/ব্যর্থ/বাতিল—সব পথেই অস্থায়ী ভিডিও ও thumbnail মুছে যায়; চ্যানেলের কপি মুছে যায় না। আর্কাইভ worker ওয়েব byte-cache তৈরি করে না। আগে ফাঁকা ডিস্ক ও `MIRROR_MAX_MB` পরীক্ষা করে; একসঙ্গে চলা download-এর জন্য ডিস্ক reservation থাকে। পাওয়ার-লস/প্রসেসে SIGKILL হলে `finally` চালানো সম্ভব নয়—হোস্টের অস্থায়ী ফাইল রয়ে যেতে পারে।
5. বটে অগ্রগতি মেসেজ (দীর্ঘ কাজে প্রায় ২০ সেকেন্ড পরপর), Pause/Resume/Stop/ব্যর্থগুলো আবার। `/admin/channels`-এ একই নিয়ন্ত্রণ, অগ্রগতি ও বিস্তারিত ত্রুটি। Pause/Stop দিলে নতুন ফাইল শুরু হবে না; সর্বোচ্চ ৩টি চলমান আপলোড শেষ হতে পারে।
6. job/items/checkpoint SQLite-এ এবং পূর্ণ ব্যাকআপে থাকে। রিস্টার্টে main scheduler নিজে থেকে অসম্পন্ন কাজ চালায়; paused/stopped অবস্থাও থাকে। আলাদা বট থেকে স্ক্যান করলেও কাজ main worker-ই করে। SQLite lease একাধিক process-কে একইসঙ্গে worker চালাতে বাধা দেয়; crash-এর পর lease expire হতে সর্বোচ্চ প্রায় ২ মিনিট লাগে।
7. সেশন না থাকলে কাজ অপেক্ষায় থাকে; অ্যাক্সেস নেই/মুছে ফেলা ফাইল থেকে সফল কপি তৈরি করা যায় না। অ্যাকাউন্টকে সোর্স চ্যানেলে বৈধভাবে থাকতে হবে। Telegram যদি download-ও প্রত্যাখ্যান করে, সেটি ত্রুটি হিসেবে দেখাবে—কোনো অ্যাক্সেস নিশ্চয়তা বা bypass দাবি নয়।

সাধারণ ডেলিভারি স্ক্রিনে raw `PeerChannel`/`source:` error দেখানো হয় না; প্রযুক্তিগত তথ্য admin diagnostics/log-এ থাকে। এই পরিবর্তনের যাচাই: **৫৩২টি টেস্ট**, যার **২৯টি** নতুন archive integration test; Telegram transferগুলো mocked, বাস্তব সেশন দিয়ে production upload আলাদাভাবে যাচাই করতে হবে। Hosting-এ নতুন কোড deploy/restart করুন (`python run.py`)।

## Desi Site — playback ও recovery আপডেট

- CodeNest `/live/<job>/` proxy-তে `data-src`/`data-stream`-ও base-relative: lazy ভিডিও, retry ও watch একই prefix রাখে।
- পুরোনো `Ahad OrgEx` ব্র্যান্ডের সেভ করা মানও এখন `Desi Site` দেখায়; স্টোর/ফাইলের নাম বা প্রকাশিত লিংক পরিবর্তন হয় না।
- অ্যাডমিন: কালো surface, হলুদ action/navigation, mobile layout অপরিবর্তিত।
- `OWNER_REPORT_BACKUP=true` (ডিফল্ট): দৈনিক রিপোর্টের সঙ্গে প্রত্যেক অ্যাডমিনকে পূর্ণ `.bfixf.gz` restore ফাইল। সফল delivery-র পরেই দিনের marker; ব্যর্থ হলে retry। ফাইলে credentials থাকে, প্রকাশ করবেন না।
- `python run.py`: প্রতি ৩০ সেকেন্ডে বাড়তি বটের process recovery; ব্যর্থ হলে ৬০ সেকেন্ড থেকে সর্বোচ্চ ১৫ মিনিট backoff। Stop দিলে disabled থাকে; Start-এ আবার চালু।
- Render-এর `PORT` child-এ থাকলেও extra bot ওয়েব সার্ভার/মূল টোকেন runner শুরু করে না। Child-এ scheduled broadcast/report/backup দ্বিতীয়বার চলে না।
- enabled বাড়তি বটের username জানা থাকলে public footer-এ বিকল্প বটের লিংক। ভিন্ন বটকে ব্যবহারকারী আগে `/start` করতে হবে; এক বটের Telegram পরিচয়/চ্যাট অন্য বট দখল করতে পারে না।
- এটি **একই হোস্টে process recovery**, আলাদা hosting failover নয়। পুরো হোস্ট বন্ধ হলে অন্য হোস্টে backup restore ও আলাদা deployment দরকার। বাস্তব ২–৩টি বট চালাতে BotFather-এর ২–৩টি ভিন্ন টোকেন যোগ করতে হবে।
- যাচাই: **৫০৩ টেস্ট পাস** + static check। Live hosting-এ code redeploy করতে হবে; Git push নিজে deployment-এর নিশ্চয়তা নয়।

## ⚡ দ্রুত শুরু

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt -r requirements-web.txt

cp config.env.example config.env
nano config.env        # API_ID, API_HASH, BOT_TOKEN, ADMIN_IDS

.venv/bin/python run.py        # ⭐ বট + ওয়েবসাইট একসাথে
```

- শুধু বট: `python bot.py` · শুধু সাইট: `python -m web.dashboard`
- **ব্রডকাস্টের জন্য bot worker চালু থাকা দরকার।** শুধু `python -m web.dashboard` চালালে

## 📊 অ্যানালিটিক্স — “কে কোথায় ক্লিক করল, কে কী দেখল”

প্রতিটি অর্থবহ কাজ `events` টেবিলে জমা হয় (`start`, `open_store`, `view_file`,
`deliver`, `join_block`, `join_click`, `limit_block`, `pay_start`, `paid`,
`search`, `add_file`, `channel_post`, `broadcast_start`, `scan` …)।

**প্রতি ইউজার** (`/admin/users/<id>`, বটে `📊 Analytics` → ইউজার):
ইউজারনেম, জয়েন/শেষ দেখা, কোন স্টোরে কতবার ঢুকল, **কোন কোন ভিডিও দেখল (কতবার,
সর্বশেষ কখন)**, সবচেয়ে বেশি সার্চ করা শব্দ, অ্যাক্সেস, অর্ডার, সাপোর্ট টিকিট,
পুরো ইভেন্ট-টাইমলাইন — আর ড্যাশবোর্ড থেকে সোজা মেসেজ/ব্যান করার বাটন।

**প্রতি স্টোর** (`/admin/analytics/store/<id>`, বটে `📊 এই স্টোরের স্ট্যাটস`):
**ফানেল** — কতজন এসেছে → কতজন জয়েন করেছে → কতজন ভিডিও দেখেছে → কতজন কিনেছে;
**কোন ভিডিও কতজন ইউনিক ইউজার দেখেছে** (views/unique/মোট পাঠানো/শেষ কখন);
**কে কী দেখেছে** (প্রতি ইউজার কতটি ভিন্ন ভিডিও); সাম্প্রতিক ইভেন্ট।

**প্রতি ফাইল** (`/admin/analytics/file/<id>`): যারা ফাইলটি পেয়েছে (কতবার, শেষ কখন)
আর **যারা জয়েন করতে পারেনি** — কতবার চেষ্টা করেছে (ফলো-আপের জন্য একদম দরকারি)।

## 📡 চ্যানেল ম্যানেজমেন্ট + চ্যানেল পোস্ট

- **চ্যানেল যোগ করুন যেকোনো রেফারেন্স দিয়ে:** `@username`, `https://t.me/…`,
  `https://t.me/+ইনভাইট`, `-100…` আইডি — অথবা চ্যানেলের যেকোনো পোস্ট **forward** করুন।
- **স্কোপ:** 🌍 সব স্টোরে (ফোর্স-জয়েন + ক্যাশ) অথবা একটা নির্দিষ্ট স্টোরের জন্য।
- প্রতি চ্যানেলে: 🔎 চেক (নাম + সদস্য সংখ্যা), 🚫 বন্ধ/চালু, 🗑 ডিলিট।
- **চ্যানেল পোস্ট (delivery):** মেসেজ + একাধিক ফাইল + **ইনলাইন URL বাটন**।
  বাটনের সিনট্যাক্স — প্রতি লাইনে একটা, `লেবেল | লিংক`; একই লাইনে `&&` দিলে পাশাপাশি:

  ```
  📢 জয়েন করুন | https://t.me/mychannel
  🟢 স্টোর খুলুন | https://t.me/mybots?start=সিনেমা_হাউস && 💬 অ্যাডমিন | https://t.me/myid
  ```

- **লিমিটেড লিংক মোড:** চ্যানেলে ভিডিও না দিয়ে শুধু একটা বাটন দেওয়া যায় — যেমন
  “🔓 ভিডিও নিন (১০০ বার)”; তারপর ঠিক ১০০ ক্লিকের পর ইউজারকে বলা হয়
  “লিমিট শেষ — অ্যাক্সেস দেওয়া হবে না”।
- পোস্টের নিচে ফিক্সড লেখা (`CHANNEL_POST_FOOTER`) আর ডিফল্ট বাটন
  (`BROADCAST_DEFAULT_BUTTONS`) প্যানেল থেকেই সেট হয়।
- 🧪 **টেস্ট: অ্যাডমিনের DM-এ আগে পাঠান** — চ্যানেলে ভুল পোস্ট যাবে না।

  ইউজারকে পাঠায়। তাই ব্রডকাস্ট সত্যিই পৌঁছায় (টেস্ট পাঠানোর সময়ই ভুল ধরাও পড়ে)।
- **🆕 সাপ্তাহিক ডাইজেস্ট** — প্যানেলে চালু করলে সপ্তাহে একদিন (দিন/ঘণ্টা সেট করা)
  নতুন আপলোড থাকা প্রতিটি স্টোরের অডিয়েন্সকে নিজে থেকেই এক ক্যাম্পেইন যায়;
  “এখনই পাঠান” বাটনও আছে।
- **🆕 বহু-মেসেজ ব্রডকাস্ট (আপনার `broadcast.py` বটের সিস্টেম এখানে যোগ করা)** —
  বটে: `/br` খুলে যা পাঠাবেন সব যোগ হবে (`/britems` তালিকা, `/brdrop` শেষটা বাদ,
  `/brpreview` ইউজার যা দেখবে, `/brsend` পাঠান) · ওয়েবে: স্টুডিওর
  “📤 পাঠানোর ধরন → বহু-মেসেজ” বেছে টেক্সট + মিডিয়া + প্রতি মিডিয়ার ক্যাপশন লিখুন।
  বাটন বসে শেষ মেসেজে (`BROADCAST_BUTTONS_ON` = last/each/none)।
- **🔗 খসড়ার পাবলিক লিংক** — `/draft/<token>`; শুধু পড়ার, কোনো অ্যাডমিন তথ্য বা
  বাটন ওখানে যায় না (কতবার খোলা হলো সেটাও গোনা হয়)।

## 🖼️ কনটেন্ট নিয়ম — শুধু ভিডিও/ছবি, টেক্সট কখনো নয়

- **সেভ হয়:** `Video` ✅ · `Photo` ✅ (প্যানেল থেকে চাইলে প্রসারিত করা যায় —
  `CONTENT_MEDIA_KINDS`)।
- **কখনো সেভ হয় না:** টেক্সট, লিংক প্রিভিউসহ মেসেজ, স্টিকার/GIF, অডিও, ভয়েস,
  ডকুমেন্ট, পোল — বরং বট স্পষ্ট করে বলে দেয় কিছুই সেভ হয়নি।
- ভিডিও/ছবি **পাঠালেই** সেভ হয় (forward করলেও), নাম হয় ক্যাপশন থেকে —
  ক্যাপশন না থাকলে `Video 3` জাতীয় নাম। ডুপ্লিকেট চারবার সেভ হয় না।
- **“যেকোনো টেক্সট দিলে বারে বারে সেভ হইতেছে”** — আসল কারণ ছিল লিংক প্রিভিউ:
  টেলিগ্রাম লিংক-সহ টেক্সটেও `media` সেট করে, তাই পুরোনো কোড প্রতিবার নতুন আইটেম
  বানাত। এখন `MessageMediaWebPage` আলাদা করে চেনা হয় এবং কিছুই লেখা হয় না।
- স্ক্যানার (চ্যানেল থেকে অটো-সংগ্রহ)-ও একই নিয়ম মানে — শুধু ভিডিও/ছবি।

## 📥 “ফাইল বোর্ডে ফরওয়ার্ড হয়ে ডিলিট হচ্ছিল” + FloodWait — সমাধান

আগে বট পড়তে না পারলে সেশন দিয়ে ফাইলটা বটের DM-এ forward করে, পাঠিয়ে, **কপিটা
ডিলিট** করে দিত। কয়েকজন একসাথে ক্লিক করলে একই ভিডিও বারবার forward-delete হত →
FloodWait, কেউ ফাইল পেত না।

এখন **মিডিয়া ক্যাশ** (`app/services/media_cache.py`):

1. যে ফাইল বট নিজে পড়তে পারে, সরাসরি পাঠায় (কিছুই কপি করে না)।
2. না পারলে **একবারই** কপি করা হয় — লক্ষ্য `STORAGE_CHANNEL` (প্যানেলে সেট করা),
   না থাকলে স্টোর-মালিকের DM — এবং `files.mirror_chat/mirror_msg`-এ মনে রাখা হয়।
3. এরপর প্রতিটি ক্লিক, সার্চ, লিমিটেড লিংক, ব্রডকাস্ট = **বটের সাধারণ send**:
   সেশন ট্রাফিক নেই, forward নেই, ডিলিট নেই, FloodWait নেই।
4. বড় ফাইল চাইলে ranged/chunked ডাউনলোড করে re-upload হয় (restricted/forward-protected
   সোর্সেও কাজ করে), `MIRROR_MAX_MB` সীমা মানে।
5. ব্যাকগ্রাউন্ড লুপ (`mirror_loop`) নিজে থেকেই ক্যাশ গরম রাখে; প্যানেলে
   **📥 সব ফাইল ক্যাশ করুন** বাটনও আছে।

### 🚨 নিরাপত্তা — এখনই করুন

1. **BotFather → `/mybots` → API Token → Revoke** করে নতুন টোকেন নিন — এবং নতুনটা
   **শুধু** `config.env` বা হোস্টিংয়ের Environment Variables-এ রাখুন, কোডে/README-তে নয়।
   (`config.env` যদি একবার রিপোতে চলে যায়, ফাইল মুছে দিলেও **পুরোনো কমিটে মানটা থেকে যায়** —
   তাই টোকেন বদলানো ছাড়া কোনো উপায় নেই। বট নিজেই এটা চিনে লগে ও অ্যাডমিনের DM-এ
   সতর্কবার্তা দেয় — `app/services/secrets_guard.py`।)
2. `/admin`-এর login password source code-এ আছে; public repo হলে সেটি গোপন থাকে না। Cookie-signing key database-এ randomভাবে তৈরি ও সংরক্ষিত হয়।
3. `/admin` পুরো স্টোর নিয়ন্ত্রণ করে — কখনো পাসওয়ার্ড ছাড়া পাবলিক রাখবেন না।

## 📡 চ্যানেলে অটো-পোস্ট (নতুন ভিডিও যোগ হলেই)

`/admin/settings` → 📣 ব্রডকাস্ট → **নতুন ভিডিও অটো-পোস্ট** চালু করে চ্যানেল বেছে দিন।
এরপর স্টোরে ভিডিও যোগ করলেই (বটে পাঠালে বা স্ক্যান করলে) চ্যানেলে চলে যায়:

- `AUTO_POST_TEXT` — পোস্টের লেখা, `{name}` = ফাইলের নাম
- `AUTO_POST_CHANNEL` — কোন চ্যানেলে (খালি রাখলে 📡 Channels-এর প্রথমটা)
- `AUTO_POST_LINK_LIMIT` — `0` = ভিডিও নিজেই যায়; `100` দিলে
  “🔓 ভিডিও নিন (১০০ বার)” বাটন যায় (ভিডিওটাই চ্যানেলে থাকে না, ক্লিক-লিমিট কাজ করে)
- সাথে ইনলাইন বাটন: “🟢 <স্টোর> খুলুন” (বট ইউজারনেম থেকে ডিপ-লিংক)

সব কাজ ব্যাকগ্রাউন্ডে হয় — আপনার আপলোড কোনোদিন অপেক্ষা করে না।

## 🌐 হোস্টিং প্যানেলের লাইভ লিঙ্ক (`/live/<job>`) — কেন কাজ করত না, কী ঠিক হলো

হোস্টিং প্যানেল (CodeNest/RunSpace, আর আপনার নিজের হোস্ট সাইট) জব চালানোর সময় ফাইলের
নাম ধরে entry point বেছে নেয়: `main.py → app.py → bot.py → server.py → index.py → run.py`।
এরপর দুটো জিনিস আশা করে:

1. `$PORT` পোর্টে (যেমন 11000) **লিসেন করা** — নইলে প্যানেল লেখে
   *“The job is running, but no web listener yet”*;
2. লিঙ্ক **`https://<panel>/live/<job>/`** আকারে দেখানো — অর্থাৎ অ্যাপকে
   `X-Forwarded-Prefix` মেনে চলতে হবে, নয়তো `/admin` বাটনে চাপ দিলে ইউজার প্যানেলের
   রুটে চলে যায় (404)।

আগে `bot.py`-এর ভিতরে ওয়েবসাইট চালানোর কোড ছিল **কিন্তু সেটা কখনো কল হত না**, আর
`WEB_ENABLED`-এর ডিফল্ট ছিল `false` — তাই জব “running” হয়েছিল কিন্তু কোনো পোর্ট খোলেনি।
এখন:

| Entry | কী করে |
|---|---|
| `main.py` (নতুন) | পুরো প্রোডাক্ট: সাইট + বট এক প্রসেসে; `$PORT` @ `0.0.0.0` |
| `bot.py` | `$PORT` থাকলে নিজেই `run.py`-তে যায় (বট রিট্রাই করে, সাইট কখনো ডাউন হয় না) |
| `run.py` | সাইট সবসময় চালু, বট কানেক্ট না হলে সাইট তবু চলবে |

- `WEB_ENABLED` ডিফল্ট **true**; হোস্টেড জবে (`$PORT` থাকলে) সাইট চালু হবেই — বন্ধ করা যায় না।
- প্রতিটা পেজে `<base href="/live/<job>/">` বসে আর লিঙ্কগুলো base-relative হয়, তাই
  মেনু, “বিস্তারিত”, ফর্ম ও ৩০৩ রিডাইরেক্ট সব লাইভ লিঙ্কের ভিতরেই থাকে।
- জানতে চাইলে: `curl http://127.0.0.1:$PORT/health` → `port`, `host`, `from_port_env`,
  `url_prefix` — এই চারটা দেখলেই বোঝা যায় প্যানেলের লিঙ্ক ঠিক আছে কি না।
- ডিপেন্ডেন্সি: প্যানেল **শুধু `requirements.txt`** ইনস্টল করে (রিপো মোডে `pip install -r
  requirements.txt`; import-স্ক্যান শুধু inline কোডের জন্য চলে)। তাই ওয়েব স্ট্যাক
  (`fastapi`, `uvicorn`, `python-multipart`) এখন `requirements.txt`-এই রাখা — আগে ওগুলো
  শুধু `requirements-web.txt`-এ ছিল, আর হোস্টেড জবে সাইটটাই চালু হত না।
- টেস্ট: `tests/test_web.py` আসল `python main.py` / `python bot.py` চালিয়ে `$PORT`
  খোলে কি না ও `/live/<job>/` প্রিফিক্স মানে কি না — দুটোই যাচাই করে।

> 💡 আপনার নিজের বানানো সাইট (group_moderator — `website-model-info` ফাইলটা) ঠিক এই
> প্যাটার্নেই চলে: `main.py`, `aiohttp`/`uvicorn` @ `0.0.0.0:$PORT`, আর পেজ থেকে
> হালকা (relative) পাথ দিয়ে `api/…` কল। আমরা এখন একই নিয়ম মেনে চলছি, তাই একই
> প্যানেলে দুটোই একসাথে চলে।

### 🔐 গোপন তথ্য zip ফাইলের ভিতরে? — এখন সেটাও ধরা পড়ে

রিপোতে একটা `.zip` (বা বাংলা নামের ফাইল, যেমন `website-model-info`) কমিট করলে
ভিতরের `core.py`-তে রাখা `API_HASH` চোখে পড়ত না — এখন প্যানেলের 🔐 Security পেজ
আর বুটের ওয়ার্নিং **zip খুলে ভিতরটাও স্ক্যান করে**, ঠিকানা দেখায় এভাবে:

    website-model-info!group_moderator/core.py:59 — b50a9c…7f0d (32 chars)

মান কখনো পুরোটা দেখানো হয় না (মাস্ক করা), আর ফাঁস হয়ে গেলে সমাধান একটাই —

## 🔐 নিরাপত্তা পেজ (`/admin/security`)

রিপো পাবলিক, তাই প্যানেল নিজেই বারবার পরীক্ষা করে দেখায়: `config.env` কমিট হয়েছে কি না,
গিট ইতিহাসে টোকেন এখনো পড়া যায় কি না, আর **রিপোর কোনো ফাইলে সরাসরি লেখা টোকেন/হ্যাশ/সেশন**
আছে কি না (নমুনা লুকিয়ে দেখায়, “…” দিয়ে — এক লাইনেই বোঝা যায় কোন ফাইলের কোন লাইন)।
স্ক্যানার **গত কমিটেও** খোঁজে: ডিস্ক থেকে ফাইল মুছে দিলেও কমিট করা পর্যন্ত টোকেন সবাই পড়তে
পারে, তাই সেটাও ধরা পড়ে। পাশে ধাপে ধাপে ঠিক করার নিয়ম: BotFather →
Revoke → নতুন টোকেন শুধু Environment Variables-এ → পুরোনো সেশন Terminate।

## ⏳ ভুল করে লেখা টেক্সট আর সেভ হবে না (প্রশ্নের সময়সীমা)

বট যখন আপনার কাছে কিছু জিজ্ঞেস করে (“চ্যানেলের লিংক দিন”, “কত ক্লিক?”), সেই প্রশ্ন
`FLOW_TIMEOUT_SECONDS` (ডিফল্ট **৬০০** = ১০ মিনিট) পর নিজে থেকেই বাতিল হয়ে যায়।
আগে প্রশ্নটা দিনের পর দিন সক্রিয় থাকত — তাই পরে আপনি যা-ই লিখতেন, সেটাই সেই
প্রশ্নের উত্তর হয়ে সেভ হয়ে যেত (একই জিনিস বারবার সেভ হওয়ার আসল কারণ)।

- প্রতিটি প্রশ্নের নিচে **✖️ বাতিল** বাটন থাকে — চাপলেই প্রশ্ন বাতিল, কিছুই সেভ হয় না।
- প্যানেলের অন্য যেকোনো বাটনে চাপ দিলেও সামনে থাকা প্রশ্নটা বাতিল হয়ে যায়।
- ভুল উত্তর পরপর **৩ বার** দিলে বট নিজেই বলে “বারবার ভুল হচ্ছে — কাজটি বাতিল করলাম”,
  তারপর প্রশ্নটা সরিয়ে দেয় (ভুল ডেটা জমতে পারে না)।
- সময় শেষ হয়ে গেলে বট স্পষ্ট করে জানায়: “⏳ আগের প্রশ্নটির সময় শেষ — কিছুই সেভ হয়নি”।
- ভ্যালুটা প্যানেল → ⚙️ Settings থেকেও বদলানো যায়; config.env-এ `FLOW_TIMEOUT_SECONDS`।

## 📊 দৈনিক রিপোর্ট (অ্যাডমিনকে নিজেই মেসেজ করে)

`OWNER_REPORT_ENABLED=true` (ডিফল্ট চালু) আর `OWNER_REPORT_HOUR=21` সেট থাকলে
প্রতিদিন রাতে অ্যাডমিনের DM-এ এক মেসেজ যায়:

🔗 লিমিট শেষ: 3 · লিংক ব্যবহার: 22
💳 অর্ডার: 2 · আয়: ৳398

এর সাথে সাপ্তাহিক **ডাইজেস্ট** (`DIGEST_*`) দিয়ে নতুন ভিডিওর ক্যাম্পেইন নিজে থেকেই
কিউ হয় — সাপ্তাহিক মেসেজটা না দিলে পুরোনো ইউজার হারিয়ে যেতে থাকে।

## 🧪 নিজের কোড যাচাই করার টুল (`tools/`)

```bash
.venv/bin/python tools/static_check.py app web tools bot.py run.py   # undefined name
.venv/bin/python -m pytest tests -q                                  # ২৮১টি টেস্ট
DB_FILE=preview.sqlite3 .venv/bin/python tools/seed_demo.py          # ডেমো ডেটা
```

`static_check.py` হলো একটা ছোট “pyflakes” — ধরতে পারে `NameError` (যেমন ডিপ্লয়ে
ঘটে গিয়েছিল: `scheduler.start_all()` কিন্তু `scheduler` import করা ছিল না —
বট কানেক্ট হওয়ার সাথে সাথেই ক্র্যাশ)। টেস্ট-স্যুটেও চলা হয়, তাই এটা আর
কখনো ফিরে আসবে না। একইভাবে `tests/test_screens.py` **৫২টি বট স্ক্রিন** একবার
একবার করে রেন্ডার করে দেখে — কোনো বাটনে চাপ দিলে স্ক্রিন খুলবে কি না।
